# Khayrat EPC 工程日报分析系统

面向伊拉克 Samawah **Khayrat 3,200 TPD 水泥粉磨站 EPC 项目**的本地化日报分析原型。系统默认不显示虚构项目数据；导入真实日报后才计算指标。内置数据仅用于演示，并始终显示“示例数据模式”。

## 推荐部署：Vercel + Supabase

正式用户只需要浏览器，不需要在 Windows 安装 Node.js、Python 或运行开发环境。推荐由管理员完成一次云端部署：Vercel 托管静态前端和 OCR/视觉服务代理，Supabase 提供邮箱登录、Postgres 数据库和私有对象存储。

### 需要准备的账号

1. GitHub、GitLab 或 Bitbucket 账号及本仓库访问权限。
2. Vercel 账号，用于导入仓库和发布公开 HTTPS 地址。
3. Supabase 项目，用于 Auth、Postgres 和 Storage。
4. 可选 OCR/视觉服务账号；仅扫描日报或真实图片识别需要。

### 部署步骤

1. 在 Supabase SQL Editor 执行 `supabase/schema.sql`，创建带 RLS 的日报、图片、导入审计表及私有 `khayrat-reports` bucket。
2. 在 Supabase Auth 中启用 Email 登录，并把 Vercel 正式域名加入允许的 Redirect URLs。
3. 在 Vercel 选择 **Add New → Project**，导入本仓库。项目会读取 `vercel.json`，运行 `npm run build` 并发布 `dist/`。
4. 在 Vercel Project Settings → Environment Variables 配置下表变量，然后重新部署。
5. 建议正式项目启用 Vercel Deployment Protection 或组织级 SSO；应用数据层还会通过 Supabase Auth 与 RLS 拒绝匿名读写。
6. 打开 Vercel 分配的 HTTPS 地址，点击页头“云端已配置 · 点击登录”，输入获准邮箱并通过邮件链接登录。

### 环境变量

| 名称 | 必需 | 保存位置 | 说明 |
|---|---|---|---|
| `SUPABASE_URL` | 云存储必需 | Vercel | Supabase Project URL |
| `SUPABASE_ANON_KEY` | 云存储必需 | Vercel | 可公开的 anon key；安全性依赖 RLS，不是 service-role key |
| `SUPABASE_STORAGE_BUCKET` | 否 | Vercel | 默认 `khayrat-reports` |
| `ACCESS_CONTROL_REQUIRED` | 建议 | Vercel | 正式环境保持 `true`；OCR/视觉代理要求 Authorization |
| `OCR_API_URL` | 扫描 PDF 可选 | Vercel | 后端 OCR 服务地址 |
| `OCR_API_KEY` | 扫描 PDF 可选 | **仅 Vercel 服务端** | 不会发送到浏览器 |
| `VISION_API_URL` | 视觉识别可选 | Vercel | 后端视觉服务地址 |
| `VISION_API_KEY` | 视觉识别可选 | **仅 Vercel 服务端** | 不会发送到浏览器 |

不得把 Supabase `service_role`、OCR 或视觉服务密钥放入 `app.js`、GitHub 仓库或任何 `VITE_*`/公开前端变量。`/api/config` 只返回允许公开的 URL、anon key 和功能开关。

### 必须由管理员手动完成

- 创建 Supabase 与 Vercel 项目、执行 SQL、配置 Redirect URL 和环境变量。
- 邀请或批准可访问项目的邮箱用户。
- 决定并配置 Vercel Deployment Protection。
- 如需扫描件 OCR 或真实视觉识别，选择合规服务、签订数据处理协议并配置服务端密钥。
- 上传一批脱敏真实日报，按本文“使用真实 PDF 验收”逐项签字确认识别准确率。

授权完成后可运行不会打印密钥值的部署前检查：

```bash
npm run cloud:preflight
```

它会检查必要变量是否存在，以及 GitHub、Vercel、Supabase API 是否可达；任一必要条件缺失时返回非零退出码，避免把“配置文件已准备”误报为“云端已部署”。

## 启动

```bash
python3 -m http.server 4173
```

访问 <http://localhost:4173>。由于使用 ES Modules，不能直接双击 `index.html`。

### Windows 用户

1. 从 [Python 官网](https://www.python.org/downloads/windows/) 安装 Python 3，安装时勾选 **Add Python to PATH**。
2. 下载或解压本项目文件夹。
3. 双击项目根目录的 `start-khayrat.bat`。脚本会启动本地服务器并在默认浏览器打开 <http://localhost:4173>。
4. 在网页中进入“日报录入”测试手工填写；或下载 Excel 模板，填写后回到页面导入。
5. 命令窗口必须保持打开。使用完毕后在窗口按 `Ctrl+C` 停止服务器。

也可以在 PowerShell 中进入项目目录后运行：

```powershell
py -m http.server 4173
Start-Process http://localhost:4173
```

## 已实现功能

- 导入 UTF-8 CSV、标准 `.xlsx`（读取首个工作表）和一个或多个 PDF 日报，支持多文件合并与重复记录去重。
- 按截止日期、车间、工序筛选，并按日报、周报、月报聚合趋势。
- 计算 WBS 加权计划/实际进度、偏差、分单位工程量、人员构成与环比变化。
- 展示主要设备的发运、到货、安装准备状态，以及日报风险和进度滞后风险。
- 识别连续停工并保留日报名称、日期和原始记录证据。
- 导出当前筛选范围的标准化 CSV，并提供中文字段模板。
- 独立“日报录入”页面，支持新增、编辑、查询、删除、字段校验和重复日报提醒。
- 手工录入和批量导入数据持久化到当前浏览器 IndexedDB，并保留 `localStorage` 兼容回退；导入时使用活动级业务键跳过真正的重复项。
- 本地数据 JSON 备份与恢复；恢复时校验格式、记录有效性并跳过重复项。
- 浏览器端生成可直接填写并可被系统重新读取的标准 `.xlsx` 模板。
- 未配置云端时数据只保存在当前浏览器；配置 Supabase 且用户登录后，原始文件和分析数据会同步到项目私有云存储，界面会明确显示连接状态和失败信息。
- PDF 默认尝试使用 PDF.js 提取多页、中英文和带位置的文本，内置解析器作为离线降级，并提取 PDF 中的 JPEG/JPX 嵌入图片；日报、页码、原始文本摘要、来源位置和提取方式随记录保留。
- 浏览器可多选 PDF，也可选择包含子目录的整个日报文件夹；相对路径作为来源保留，原始 PDF 上传到私有对象存储。
- “图片证据”页面支持缩略图、大图、日期/车间/工序/日报筛选、关键证据、忽略、人工改标签、场景、证据类型及日报关联。
- 图片证据可关联车间进度、设备到货/安装准备、风险和连续停工记录；日报文本与图片场景冲突时显示“待人工复核”。

## 输入数据结构

CSV 首行或 Excel 首行是字段名。支持以下中文名，也支持代码中定义的英文别名：

| 字段 | 类型 | 说明 |
|---|---|---|
| 日报名称 | 文本 | 证据来源名称 |
| 日期 | `YYYY-MM-DD` | 必填 |
| 车间、工序 | 文本 | 对比和停工识别维度 |
| 计划进度、实际进度 | 数值 | 百分数，可写 `23.5` 或 `23.5%` |
| 实际完成工作量、累计完成量 | 数值 | 兼容旧字段“当日混凝土、累计混凝土” |
| 工作量单位 | 文本 | 如 m³、t、项 |
| 中方人员、属地人员 | 整数 | 现场人员数量 |
| 设备名称、设备状态 | 文本 | 如已发运、已到货、安装准备中 |
| 风险制约 | 文本 | 影响施工或安装的风险 |
| 工作状态 | 文本 | 如施工中、停工、完成 |
| 原始记录 | 文本 | 用于证据追溯的日报原文 |

字段标准化与别名映射位于 `src/analytics.js`，文件解析器采用适配器结构。Excel 模板字段与这些导入别名保持一致。`src/xlsx-writer.js` 在浏览器中生成标准 OOXML 文件，不需要上传模板或数据。

## PDF 与图片证据流程

1. CSV、Excel 和 PDF 各自由适配器解析，输出相同的标准日报对象；导入前先显示记录、重复项、图片和错误预览，确认后才通过事务写入，后续分析共用一套逻辑。
2. PDF 优先动态加载 PDF.js，按页提取文字和坐标；不可用时降级到支持未压缩或 `FlateDecode` 内容流的内置解析器。无法映射的关键字段进入 `reviewFields`，不会补造数值。
3. PDF 中使用 `DCTDecode`（JPEG）或 `JPXDecode` 的嵌入图片只在导入页面内存中临时表示，随后上传到私有 Storage；持久层只记录唯一 `imageId`、对象路径、文件名、页码、页内顺序、邻近文字和日报关联。
4. 未配置视觉服务时，基础分析器只根据文件名、邻近文字和人工元数据分类，并明确提示“尚未启用真实视觉识别”。`ImageAnalysisProvider` 可在用户授权后把像素数据发送到受控后端；前端不保存 API 密钥。
5. 人工复核可以修改日期、车间、工序、关联日报、场景、标签、说明和证据类型，也可以标为关键证据或忽略。
6. 无论置信度高低，AI 推断都不能单独作为停工、设备到货或质量验收结论；最终状态必须人工确认或有其他直接记录支撑。

手工和表格日报保存在 IndexedDB 轻量缓存；PDF 批次采用下述云端优先顺序，把原始 PDF、结构化日报、图片和导入审计保存到 Supabase 后再落本地元数据，以便跨设备访问。

### PDF 与图片存储顺序

PDF 导入采用云端优先事务流程，避免浏览器存储配额中断上传：

1. 选择文件前确认 Supabase 已配置且用户已登录；未认证时 PDF 导入不会启动。
2. PDF 仅在当前页面内存中解析和预览，不把原始 PDF 或 Base64 图片写入 `localStorage`。
3. 用户确认后，先把原始 PDF 和提取图片上传到私有 `khayrat-reports` bucket；对象路径包含稳定的导入批次 ID。
4. 全部对象上传成功后，以 upsert 方式保存日报、图片元数据和导入审计，再写入不含二进制内容的本地轻量缓存。
5. 部分上传失败时保留当前批次和进度，按钮变为“重试失败上传”；相同批次和对象路径会安全覆盖，不会新增重复统计。
6. 图片展示使用短期签名 URL，重新登录或刷新页面时重新签发；数据库和浏览器元数据中不保存公开图片地址。

旧版本已经存在的浏览器数据不会在启动时被自动清除。读取到旧 IndexedDB 图片时可以继续在当前会话使用；下一次成功云端导入/同步后只保留轻量元数据。建议确认云端文件完整后再手动清理旧站点数据。

## 本地数据与防重复规则

- 手工保存、CSV/XLSX 导入和 JSON 恢复最终都进入同一个本地数据仓库。
- 活动级业务键为 **日期 + 车间 + 工序 + 活动编号**；没有活动编号时使用设备及原始记录摘要。同日同车间同工序的不同活动会保留，完全相同的活动才会跳过。
- “备份数据”下载包含格式版本、日报记录及图片证据的 JSON 文件；“恢复备份”只接受这一格式。
- IndexedDB 和 `localStorage` 都不是云存储。清理站点数据、重装浏览器或更换电脑都可能丢失数据，日常使用应定期备份。

## 数据口径修正

- 项目总体计划和实际进度只在存在有效 `WBS权重` 时计算加权值；没有权重时总体值显示为空，仅展示车间/工序分项，简单平均不再冒充正式总体进度。
- 工程量严格按“车间 + 工序 + 工作量单位”分组，m³、t、项等不同单位不会相加。
- `人员口径` 区分项目总人数与车间施工人数；项目人数趋势只读取“项目总人数”，`工种`保留作进一步资源分析。
- 停工需要日报明确标注停工，或同时满足进度无变化、工程量无变化且该工序人员为零；仅仅当日混凝土为零不会再判为停工。

## Google Drive 只读同步方案

代码中已提供 `GoogleDriveReadOnlyAdapter` 接口骨架，但界面暂不启用账号授权。计划流程是：

1. 管理员在 Google Cloud Console 创建 **OAuth 2.0 Web Client**，配置实际部署域名，并在运行环境中提供 Client ID 和项目文件夹 ID。
2. 前端使用 Google Identity Services 弹出授权，仅请求 `drive.readonly` 最小权限；用户在 Google 官方页面登录，应用不接触账号密码。
3. 通过 Drive API 查询指定文件夹的 CSV/XLSX 文件，用 `id + modifiedTime + md5Checksum` 判断新增或变化文件。
4. 下载内容后复用现有 CSV/XLSX 适配器、标准化、校验和业务键去重流程。
5. 访问令牌只保存在页面运行内存中，退出或过期后重新授权；Client Secret、刷新令牌、账号密码和私有凭据不得写入前端或仓库。

双向写回、后台定时同步和冲突解决不在当前阶段范围内。

## 计算口径

- **总体进度**：只对存在正数 WBS 权重的最新活动记录加权计算；缺少权重时显示空状态。
- **人员数量**：项目趋势只读取“项目总人数”口径，同一日期取中方/属地人数的项目级记录，避免车间和工种明细重复累加。
- **完成量**：按车间、工序和单位分别统计当日及累计值，不对不同单位求和。
- **关键节点滞后**：最新实际进度比计划进度低至少 5 个百分点。
- **连续停工**：同一“车间 + 工序”连续至少 **3 个有效日报日**明确标注停工，或同时满足进度无变化、工程量无变化且人员为零。仅工程量为零不会触发。这里的“连续”指连续上报记录，不推断缺失日期。

### 使用真实 PDF 验收

1. 准备一份可搜索文字的多页中英文日报，以及一份扫描型日报；备份敏感信息后再测试。
2. 在“日报数据导入”选择 PDF，先检查导入预览中的来源、日期、车间、工序、重复项和错误，不确认则不会写入。
3. 导入后在历史日报逐页核对原文片段、人员数量、工程量单位和数值；缺失字段应显示待复核。
4. 在“图片证据”核对照片页码、编号、邻近说明和日报关联。未配置视觉后端时页面必须提示未启用真实视觉识别。
5. 扫描页只有在用户授权并配置 OCR Provider 后才允许发送处理；当前仓库不包含 OCR 服务或任何外部 API 密钥。
6. 测试完成后导出 JSON 备份，再恢复到新的浏览器配置，核对日报和图片数量。

## 尚未实现

- OCR Provider 已定义授权和后端边界，但仓库未内置 OCR 模型或服务；扫描型 PDF 在未配置时会标记未授权 OCR。
- PDF.js 通过固定版本 CDN 动态加载；完全离线时使用能力较弱的内置降级解析器。生产部署应自托管 PDF.js 文件。
- 复杂跨页/合并单元格表格和少数字体编码仍可能需要人工复核。
- Flate 压缩原始像素图、JBIG2 等 PDF 图片格式的浏览器转换；当前图片提取聚焦 JPEG/JPX 嵌入图。
- 真正读取图片像素的高级视觉模型；当前版本为规则、邻近文字和人工标注工作流。
- Google Identity Services 的实际 UI 授权和 Google Drive 在线同步（当前只有可测试的只读适配器骨架）。
- 精细项目角色、审批流及多人同时编辑的冲突解决；当前云端权限为 authenticated 项目成员统一策略。
- 从 Primavera P6 / Microsoft Project 自动导入 WBS 基准；当前可通过日报字段或模板提供 WBS 权重。
- XLSX 解析器目前读取首个工作表，不处理宏、公式计算结果之外的公式求值、合并单元格语义和旧版 `.xls`。
